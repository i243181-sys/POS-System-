1. Executive Summary

SecureStore POS is a professional desktop point-of-sale system designed for small and medium retail shops. It helps the shop owner control billing, stock, customer dues, reports, user access, and backups from one local application.

The main value is simple: the shop can make sales faster, reduce manual stock mistakes, keep customer purchase and due records, and protect business data through automatic verified backups.

Recommended client pitch: Instead of paying monthly forever for a generic POS, the client can buy a complete local desktop POS package for Rs 95,000 and continue using it without mandatory monthly software rent.

2. Business Problems Solved

Manual Billing Problems

  • Slow checkout during busy hours.
  • Calculation mistakes in totals, discounts, and change.
  • No proper invoice history.
  • Hard to track pending customer balances.

Inventory Problems

  • Stock is not reduced automatically after sale.
  • Low-stock products are missed.
  • No clear stock movement history.
  • Manual stock adjustments are hard to audit.

Security Problems

  • Anyone can change records if there are no roles.
  • No audit trail for sensitive actions.
  • Password sharing is common in small shops.
  • No safe backup habit.

Reporting Problems

  • Daily sales are difficult to summarize.
  • Product-wise and cashier-wise performance is unclear.
  • Profit and stock decisions become guesswork.
  • Old bills are hard to find.

3. Proposed Solution

The proposed system is a desktop POS application built with Electron, React, TypeScript, Node.js, and SQLite. It runs locally on the shop computer, so the shop does not depend on an internet connection for daily billing.

Area How It Works Client Benefit
Checkout Cashier searches products, adds items to cart, enters customer and paid amount, then completes sale. Fast, accurate billing with invoice and receipt.
Inventory Stock is reduced automatically after sale. Manual stock changes require a reason. Better stock control and fewer missing-item surprises.
Customer Dues If payment is less than the bill total, the sale is marked pending and linked to customer details. Shop can track outstanding balances.
Security Admin and cashier roles, bcrypt password hashing, session timeout, failed login tracking. Owner controls who can access management screens.
Backups Manual and automatic backups are created in a separate backup folder and verified with checksums. Business data is protected from accidental loss.

6. How the System Works

Daily Sales Flow

Step Action System Result
1 Cashier signs in. System starts secure session and applies role permissions.
2 Cashier searches/selects products. System shows active products and available stock.
3 Items are added to cart. Subtotal, discount, tax, total, amount due, and change are calculated.
4 Customer name/phone and paid amount are entered. Customer is created or reused, and pending balance is tracked if payment is incomplete.
5 Sale is completed. Sale, items, payment, stock reduction, inventory log, and audit log are saved in one transaction.
6 Receipt is printed or saved. Customer receives bill and shop record remains searchable.

Data Storage Flow

The application stores business data in a local SQLite database. The normal live database and backup files are kept separate.

Item Linux Path Windows Equivalent
Live database ~/.config/securestore-pos/SecureStorePOS.db C:\Users\<User>\AppData\Roaming\securestore-pos\SecureStorePOS.db
Backup folder ~/.config/securestore-pos/Backups/ C:\Users\<User>\AppData\Roaming\securestore-pos\Backups\
Backup metadata *.db.json *.db.json
Current verification: the live database already contains Users, Products, Customers, Sales, SaleItems, Payments, InventoryTransactions, AuditLogs, Settings, and BackupLogs tables.

7. Security and Reliability

Security Controls

  • Password hashing through bcrypt.
  • Backend-only database access through Electron IPC.
  • Role checks for admin-only actions.
  • Prepared SQLite statements.
  • Safe public error messages.
  • Audit logs for sensitive work.

Reliability Controls

  • SQLite WAL mode for crash-safe committed transactions.
  • Foreign-key checks enabled.
  • Sale completion uses transaction-safe logic.
  • Backups are verified before being accepted.
  • Restore creates a safety backup first.
  • Automatic backup scheduler is enabled.
